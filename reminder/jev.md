# JEV：判断节点与后续设计

TypeSafe System One（JEV）是决策模型，不是聊天或摘要模型。接受状态与类型化问题，返回选择、真假或分数等结构化结果。概率是模型推断，不是已发生的世界状态，也不保证正确。

## 已实现

- 渠道 `protocol: systemone`，服务商可用 `typesafe` 或兼容端点；端点是原样 POST 的完整 URL，不拼 `/chat/completions`。这类渠道不做统一 `/models` 发现。
- 只有 Flow 的 `judge` 节点调用 [internal/judge](../core/internal/judge)。节点接受 `state` 输入及配置的渠道、模型、问题、答案类型等；可输出答案 JSON 或指定键的结果。没有普通 Agent 的 JEV 开关。
- 判断结果是图中的材料，不自动进入 `messages` 或 `<state>`。现有判断节点调用失败按图的执行错误处理，不会自己创造默认答案。

## 待定：分支与 RPG 决策

可以先用有限动作集验证「JEV 给概率 → 程序按阈值选择 → 对话模型写正文」。例如 NPC 的候选是搭话、忽略、离开；先用固定场景样本检查默认分支和误判代价，再扩大动作集。阈值不能只照抄一个 `0.9`。

如果引入 Switch，要先定义不走的分支是否跳过执行、超时/失败何时走默认分支。判断材料应追加在请求尾部以维持稳定前缀；除非后续步骤明确写入消息，推断不变成世界事实。多角色并行生成会增加调用与首字延迟，不是 JEV 本身的能力，也不是当前计划。见 [TODO.md](../TODO.md#后续设计未排期)。
