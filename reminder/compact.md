# 压缩：区间装配、合并与剪枝

**压缩不删原文。** `compact` 生成摘要，`store.RecordSummary` / `RecordSummaryBatch` 在事务里复核区间并同时写摘要和覆盖关系。压缩失败或落库前取消不改变覆盖；再提交仍按原历史计算。术语见 [DEFINE.md](../DEFINE.md)。

## 取材与触发

- 底层从最早未覆盖位置取至多 N 个完整闭合块（默认 `chat.compact_blocks=3`）；开着的尾块不压。没有可压消息块时尝试合并恰好 N 条首尾相接、同层、顶层摘要，合并至少两条。显式消息区间也不能切开块或穿过覆盖空档。
- 消息级用原文剔除 `<state>` 后的正文与实际工具记录；工具结果过长会截断。合并级用孩子摘要正文。两级都从原始历史现算段首和段末的世界状态，需要时附给模型，不把状态当摘要存档。模板示例必须与真实材料抬头一致。
- 手动预览只计划区间或构造请求；真压缩通过同一准备路径。高级分段压缩可以并发调上游，受渠道并发限制；所有分段都成功才一次提交。队列逐步提交，不具备跨步骤回滚。
- **自动压缩已实现，默认关。** `chat.auto_compact` 开启后，普通对话结束翻到 idle 再检查占用；默认触发线为输入预算的 80%，可用 `compact_trigger_tokens` 覆盖。到线后逐批压，低于 50%、无可压缩材料、上游失败或本批没有缩减时停止。不阻塞后续对话。

## 装配和撤销

[state](../core/internal/state) 按消息顺序往前走；走到覆盖区间左端时选择左端对齐的最粗可用祖先，发送摘要并跳到区间末尾之后。有断指针或缺失端点时退回更细层/原文，不猜覆盖位置。Flow 的 `history` 取原始正文，不走这个摘要跳转。

例如 `A B C D E F G` 中，`B..D`、`E..F` 两份摘要合成 `B..F`，出站取 `A、B..F 的父摘要、G`。编辑仍保留区间并标 `dirty`；后缀删除移除相交的摘要和祖先；撤销较早顶层摘要时连同其后同层顶层摘要移除。原始消息与工具记录不会因撤销压缩而改写。

占用与自动压缩按最终 SDK 请求输入估算，计入工具声明、调用结果和会话覆盖。在压缩前后的同一尺度比较，不用摘要的字数代替输入开销。回归见 [autocompact_test.go](../core/internal/chat/autocompact_test.go) 和 [turn_test.go](../core/internal/turn/turn_test.go)。

## 剪枝待定

现在可导入导出含分层摘要的会话，但没有清除原文的归档功能。直接删原文会触发摘要级联，也会失去世界状态的演算材料。先决定怎么恢复会话、保留可追溯的摘要与世界状态；实施时先导出，再在事务内修改覆盖关系与存档，并报告实际删减数量。待办见 [TODO.md](../TODO.md#后续设计未排期)。
